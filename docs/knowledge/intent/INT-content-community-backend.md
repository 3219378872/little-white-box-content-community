# 小白盒内容社区后端

本仓库为小白盒内容社区提供后端能力。

## 目标

内容社区是产品主体和建设优先级。已认证用户能够创建、发布、互动和一对一交流；任何人都能按权限
阅读已发布内容，并通过关注流、搜索和个性化推荐发现相关帖子。小白盒 Agent 是帮助用户使用内容
社区的工具，不是独立的通用 AI 伙伴产品；社区核心能力和普通发现入口不以使用 Agent 为前提。

Agent 重点处理一次关键词检索难以直接解决的复杂自然语言需求，例如选择适合自身条件的猫粮、判断
什么样的狗适合自己。它通过必要的澄清、多轮检索、比较和综合，帮助用户找到、理解和使用社区内容，
最终交付符合用户条件的自然语言回答，而不是只返回搜索结果列表。

Agent 优先利用社区内容；社区资料不足以解决全部或部分问题时，继续利用互联网搜索引擎尽力回答，
并坦率说明社区尚不能解决的具体部分。来自站内外资料的每条实质性信息都应提供对应帖子或网络资源
的 URL；综合判断须说明依据和不确定性，不把外部资料包装成社区结论，也不以编造填补信息缺口。

Agent 仍位于消息页固定置顶的虚拟线程，保留会话、离线续跑和 Watch 主动消息能力。普通对话可以
自然进行，不强制检索或引用；MEMORY/USER、历史与工具服务于用户的社区任务。平台工具始终受用户
授权、本人权限、参数校验、执行预算、审计和逐次删除确认约束。

## 成功标准

- 内容生命周期、权限和可见性对调用者可预测：草稿仅作者可见，已发布内容匿名可读，取消发布或
  删除后不再出现在普通读取、发现或 Agent 工具结果中。
- 写操作可区分未认证、无权限、不存在、参数错误、版本冲突、幂等冲突和暂时不可用；权威写入未
  确认不得报成功，异步派生效果失败不得诱导重复写入。
- 关注流、搜索和推荐只返回当前访问者可见的已发布内容；可见性无法验证时失败关闭。
- 复杂需求通过 `ask_questions` 工具按需澄清，优先使用选择题并允许文字补充；追问到足以明确
  搜索目标、适用条件、硬约束和比较重点，不重复询问已知信息，也不要求填满无关资料。
- 用户可回答“不知道/没有偏好”、跳过或要求先搜索；Agent 保留未知条件，不替用户编造答案或偏好，
  可以先检索并给出分情况建议。检索发现新的关键缺口时可再次追问，并尊重已明确跳过的内容。
- 社区资料不足时不止步于无结果，使用互联网补充并说明不足；检索故障与资料不足必须明确区分。
  外部资料仍不足或相互矛盾时，如实说明可支持的结论与限制。
- 检索回答逐项关联支持该信息的具体帖子或网页 URL，区分资料陈述、个人经验和 Agent 综合判断；
  评价是否理解条件、有效利用资料并解决问题，不以聊天时长或单纯返回链接衡量成功。
- Agent 请求先持久化再异步执行。客户端断线不取消任务；worker 崩溃后从已提交步骤恢复，成功的
  工具副作用不重复执行。
- 用户 run 只在执行 `delete_post` 前逐次确认；所有工具仍受服务端授权、所有权和审计边界约束。
- MEMORY 与 USER 是用户可见、可编辑、可删除、可撤销的自然语言条目，不是模型推断形成的隐藏
  画像；普通写入不改变当前未压缩会话的冻结 prompt。
- Agent 可检索本人一年内的 Assistant 历史，但永远不能检索普通用户之间的私信；历史索引命中
  在返回前必须回源 MySQL 校验用户归属、删除状态与保留期。
- 来源必须来自实际检索并经服务端验证的资料，不能从模型生成的链接推定可信来源；普通对话不强制
  来源，基于检索资料回答复杂需求时则必须逐项引用。来源卡是可选展示方式，不能代替信息与 URL 的关联。
- Watch 由内容或行为事件触发，按窗口合并并限流，通过 Assistant 虚拟线程主动投递；不构成
  点赞、评论、关注通知中心或推送产品。
- 长任务受明确资源硬预算控制；预警只进入观测和模型不可见收敛提示，真正触顶返回
  `AGENT_RESOURCE_LIMIT`，并保留部分文本与已完成副作用摘要。
- 搜索、推荐与 Agent 的正式质量门禁和月度 SLO 必须建立在人类评审冻结集与真实生产观测上；
  合成数据只能验证工具和报告管线。

## 范围

- 注册、登录、资料维护和一对一关注关系。
- 帖子草稿/发布/取消发布/删除、评论、图片媒体、点赞、收藏。
- 一对一私信（文本与已上传媒体），以及消息页中的“小白盒 Agent”虚拟线程。
- 关注流、综合搜索（帖子/用户/标签）和个性化或冷启动推荐。
- 持久异步 Agent：复杂需求澄清、社区优先检索、互联网补充、带逐项 URL 引用的综合回答，以及
  辅助对话、Assistant 历史搜索、本人帖子读写、推荐、自然语言 MEMORY/USER 与 Watch 任务。
- Agent 永久前台会话、运行状态、断线续流、停止/转向/排队、30 分钟冷对话拼接、清除历史、compact、后台记忆审查。
- 客户端行为接收、保留期限、关闭个性化、健康检查与 SLO 口径。

## 非目标

- 账户注销、申诉、管理后台、内容审核工作流。
- 以独立通用聊天或长期陪伴产品为目标扩张 Agent；Agent 不取代社区和普通搜索、推荐入口。
- 群聊、普通私信撤回或删除，以及赞/评/关通知中心或系统推送。
- 创建机器人用户，或把 Agent 虚拟线程写入普通私信的 conversation/message 模型。
- 用户编辑 SOUL、模型提示词或工具 schema；SOUL 是 human-owned 的仓库版本化资产。
- Agent 自动评论、自动给其他用户发私信、自动购买，或访问未授权平台能力。
- 检索普通用户私信、账户 secret、验证码、未发布内容或其他用户 MEMORY/USER。
- 要求普通闲聊逐句附来源，或强制所有引用都展示为来源卡；不得把模型自行生成的 ID、链接或引用
  当作已检索、已验证的资料，也不承诺在资料不足时一定给出确定答案。
- 跨会话匿名画像，以及登录后自动合并匿名历史。
- 学习排序效果宣传（未达到曝光与身份门槛前）。

## 约束

- “应该做什么”只由本意图和引用它的已批准规范决定；技术方案、服务拆分和存储选型不属于本层。
- 本修订由人类批准，允许删除旧同步 `/api/v2/assistant/chat`、`mode` 字段和 Watch hits API，
  不提供兼容适配层。
- 破坏其它已发布契约必须使用新版本，或先修改并重新批准对应规范。
- 正式评测与 SLO 门禁不得用伪造标注或伪造生产观测关闭。
