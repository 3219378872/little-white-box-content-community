# 帖子命令指纹兼容说明

本页为非正式发布指南，不替代已批准的 CORE-050/051 或真实数据库验收。

## 新建帖子的 v2 指纹

`post:create:v2` 域标识、每段字节长度和数组元素数量共同形成无歧义编码，仍存为 64 字符 SHA-256
hex。标题、正文、图片和标签元素、媒体 ID、状态均保留原始顺序与边界；NUL、逗号、Unicode 和
空元素不会合并字段。nil 与空列表等价，符合 protobuf repeated 的传输语义。无需 SQL 列宽迁移。

## 历史幂等键

旧记录只保存摘要，没有创建命令全文；当前帖子和标签可被编辑，不能据此证明原始请求内容。
因此不能给所有请求同时接受旧摘要。仅下列可无歧义解释的旧请求保留重放：

- 标题、正文和图片不含 NUL；图片非空且不含逗号
- 标签不超过一个，且该标签不含逗号或 NUL；旧逻辑忽略空标签，因此零标签与单个空标签的效果等价
- 媒体 ID 不超过一个，避免旧排序编码丢失可观察的附件顺序

其余历史键即使是原请求重试，也会返回既有的幂等冲突错误。不会用同键创建新资源，不会接受
另一条有相同旧摘要的命令，也不会自动删除或重写历史绑定。发布前应告知调用方该限制；遇到冲突先
查询并确认原操作结果，不得自动改键重新创建。不要清空幂等表作为迁移手段。

新 v2 键的完全相同请求正常重放，不同输入返回冲突。逐步发布时旧实例不认识 v2 摘要，可能将
新实例创建的键重试判为冲突；应协调升级内容服务写实例。回滚旧实现同样保留此限制，不能承诺跨版本
全量重试兼容。兼容读取暂不设任意到期时间，移除前需另行定义保留期和迁移方案。

## 图片引用

帖子新引用只接受本人、上传完成、`file_type=image` 且权威 URL 非空的媒体。音视频继续用于
各自匹配的消息类型。历史无媒体 ID 的旧图片 URL 保留原局部更新规则；不自动删除媒体对象或修复
历史数据。真实 MySQL 并发重放、线上历史记录检查及客户端升级验收仍需在发布前完成。

## 回复目标与标签 presence 的增量契约

REST `replyToCommentId` 与 RPC `reply_to_comment_id` 指明实际被回复的可见根评论或子评论；
`parentId` 仍为根评论。服务端验证同帖、同根、目标可见和目标作者与 `replyUserId` 相符。
不提供目标或显式选择根评论使用旧指纹，历史根回复重试兼容；子回复使用包含实际目标的新指纹。

RPC `tags_provided` 携带标签列表的显式出现状态。Gateway 和 Assistant 适配器均设置此字段；
空数组清空标签，缺省保留，旧客户端的非空标签继续可用。指纹只为显式空标签增加 presence，保留
旧缺省及非空命令哈希；清空后的相同请求重放，不会再增加 revision。

应先升级全部内容服务写实例，再启用新 Gateway/Assistant/前端契约。旧服务会忽略新 protobuf 字段，
无法执行空标签清空，或拒绝新子回复。不要将滚动升级期间的旧实例行为误报为修复完成。完整真实
Gateway/Kitex/MySQL 路径与 Flutter 运行验收仍属于独立发布门禁。
