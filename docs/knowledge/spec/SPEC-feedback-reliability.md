# 行为闭环与服务可靠性规范

## 范围与术语

本规范定义行为反馈、隐私保留、可观测性、SLO 和故障降级，不规定消息中间件、分析数据库、指标系统
或部署拓扑。

- **已接受事件**：通过校验并进入系统承诺的可靠消息边界、可被后续去重和处理的事件。
- **业务效果**：事件对特征、统计、推荐或其他下游状态产生的可观察影响。
- **降级**：依赖故障时保留边界清晰的有限能力，而不是伪造正常结果。

## 行为事件与所有权

- `REL-001`：客户端只可提交 `exposure`、`click`、`dwell`、`view`、`play`、`share`、`hide` 和
  `dislike`；`like`、`unlike`、`favorite`、`unfavorite`、`comment`、`follow`、`unfollow` 只由对应
  权威业务事务和 outbox 生成，客户端提交时必须拒绝。
- `REL-002`：每个客户端事件使用最长 128 字符且全局唯一的事件标识，包含动作、目标、发生时间和场景；
  每批最多 100 条。
- `REL-003`：事件关联已认证用户或当前匿名会话；发现行为携带请求、会话、场景和从 1 开始的位置，
  并原样回传适用的召回来源、规则或模型版本和实验标识。
- `REL-004`：曝光的产品定义是同一推荐请求中的帖子至少 50% 可见并连续保持 1 秒。该视口与时长由
  客户端在提交前判定；服务端验收该声明，并强制同一 `(requestId, postId)` 最多记录一次曝光，
  不二次测量客户端视口。
- `REL-005`：停留类事件必须携带非负有效时长；只被召回但未曝光的内容不得作为负反馈。
- `REL-006`：事件最多可补报 30 天，客户端时间最多超前服务端 5 分钟；过期、超前、缺少身份或结构
  无效的事件必须逐项拒绝并返回可归类原因。
- `REL-007`：批量请求逐项返回接受或拒绝结果；只有进入可靠消息边界的事件可以报告为已接受。
- `REL-008`：同一事件在 90 天内最多产生一次业务效果；重试、消息重投和消费者重启不得重复累计。

## 反馈闭环

- `REL-010`：已接受事件能够按请求、身份、内容、位置、来源、版本和实验关联，以区分候选、曝光和动作。
- `REL-011`：拒绝或未去重事件不得进入训练和在线特征；规则、模型和降级结果必须分开归因。
- `REL-012`：接口接受成功只表示进入可靠消息边界，不表示分析或推荐特征已经更新。
- `REL-013`：反馈异步处理必须可观察延迟、失败、重试、积压和死信；历史重放不得改变去重语义。

## 隐私、保留与个性化控制

- `REL-020`：原始行为保留 90 天，推荐在线特征保留 30 天，去重记录保留 90 天，死信保留 7 天，
  去标识聚合结果最长保留 365 天；Assistant 原始消息保留 365 天，Watch 内部 hit/execution 保留
  90 天。到期数据必须自动删除并传播到派生索引。
- `REL-021`：完整客户端 IP 不得写入行为分析表；安全访问日志最多保留 7 天。
- `REL-022`：业务日志最多保留 30 天，不得记录 secret、完整手机号、验证码、私信正文、Assistant
  全量输入或社区正文。
- `REL-023`：系统必须向已认证用户提供关闭个性化的能力；关闭后立即停止将新行为用于个性化，并在
  24 小时内删除在线特征。
- `REL-024`：关闭个性化前的原始事件按 90 天期限删除，不得在关闭后继续生成用户画像；匿名行为不得
  与后续登录身份自动合并。

## SLO 计算口径

- `REL-030`：SLO 按 UTC 自然月统计。分母为到达服务且满足公开契约的请求；参数错误、未认证、无权限、
  限流、客户端取消和证据不足的正确拒答不计为不可用。
- `REL-031`：符合规范且明确标记的降级结果计为可用；错误成功、越权、无证据回答和不可见内容泄漏
  均计为不可用。
- `REL-032`：HTTP/RPC 延迟从服务接受请求到完整响应结束；Assistant 接收延迟到消息与 run 持久化，
  首事件到第一条持久事件，完成延迟到终止事件。断线不缩短 run 延迟，长任务按 elapsed/idle、
  queue age 与阶段分别观察。延迟分位数只统计契约有效且服务实际处理的请求。
- `REL-033`：月度可用性与 p95 延迟目标如下。关闭本条必须使用真实生产观测；合成观测只能验证报告
  管线。

| 能力 | 月可用性 | p95 延迟 |
| --- | ---: | ---: |
| 社区核心读取 | 99.9% | 300 ms |
| 社区核心写入 | 99.9% | 500 ms |
| 行为接收 | 99.9% | 300 ms |
| 关注流、搜索、推荐 | 99.5% | 800 ms |
| Assistant 接收 | 99.0% | 500 ms |
| Assistant 首个事件 | 99.0% | 2 s |
| Assistant 普通完成（观测目标） | 不作可用性门禁 | 45 s |
| Watch 命中到主动消息 | 99.0% | 5 min |

Assistant 活跃 run 的持久心跳间隔不得超过 30 秒；长任务不设统一完成 SLO，不能把超过 45 秒但仍
有心跳且未触顶的运行判成不可用。

## 异步、恢复与数据安全目标

- `REL-040`：业务 outbox 投递延迟为 p95 30 秒、p99 5 分钟。
- `REL-041`：行为接受到分析与推荐特征可见为 p95 60 秒、p99 5 分钟。
- `REL-042`：内容发布或更新到搜索可见为 p95 30 秒、p99 2 分钟；取消发布或删除不得继续出现在新的
  发现或 Assistant 响应中，不适用该异步放宽。
- `REL-043`：已确认提交的权威业务写入要求 RPO 0；单组件故障恢复目标 RTO 为 30 分钟。
- `REL-044`：服务恢复后接受合法新请求，并对故障期间保留的可重试工作执行有界恢复，不得形成重试风暴。
- `REL-045`：Assistant run 使用 60 秒数据库租约并每 10 秒续租；worker 崩溃后从已提交 step 恢复，
  command journal 保证已成功工具副作用不重复执行。Redis 通知故障不得丢失 MySQL 持久事件。

## 可观测性与健康

- `REL-050`：社区核心、发现、Assistant 和行为链路可观察请求量、成功率、错误类别、延迟和降级状态。
  Assistant 额外观察 run elapsed/idle、rounds、tool calls、input/output/cache tokens、cost、queue age、
  lease recovery、compact、BM25、Watch、memory-review 和 Redis 通知降级。
- `REL-051`：异步链路可观察接收、拒绝、重复、失败、重试、死信、积压和端到端延迟。
- `REL-052`：同一请求跨能力调用保留可关联的请求或追踪标识，且观测数据遵守隐私要求。
- `REL-053`：健康检查分为存活与就绪；就绪响应列出必需依赖及其状态。可选发现能力故障不使整个
  Gateway 下线，但必须报告 `degraded`。

## 故障降级矩阵

- `REL-054`：发生下表故障时必须表现出规定行为。点赞/评论/关注的站内通知中心不在当前产品范围，
  不构成独立故障行。

| ID | 故障 | 规定行为 |
| --- | --- | --- |
| REL-054-01 | 权威数据库不可用 | 返回 503，不得返回成功 |
| REL-054-02 | Redis 或缓存不可用 | 可以回源；权威写入已提交则返回成功 |
| REL-054-03 | MQ relay 不可用 | 业务与 outbox 同事务成功，异步效果延迟并告警 |
| REL-054-04 | 行为 Broker 不可用 | 行为接收返回 503 |
| REL-054-05 | 部分推荐来源或排序不可用 | 返回标记来源的规则降级结果 |
| REL-054-06 | 内容可见性检查不可用 | 发现和 Assistant 失败关闭 |
| REL-054-07 | 帖子搜索索引不可用 | 搜索返回 503 |
| REL-054-08 | LLM transport 不可用 | run 以明确错误终止，保留已提交部分文本、来源卡与副作用摘要 |
| REL-054-09 | Assistant MySQL 状态存储不可用 | 拒绝接受新 run，不得同步执行或伪造已排队 |
| REL-054-10 | 指标后端不可用 | 业务继续，保留本地日志并产生监控缺口告警 |
| REL-054-11 | Assistant Redis 通知不可用 | 事件仍先写 MySQL；SSE 以 MySQL 轮询补齐 |
| REL-054-12 | Assistant worker 崩溃 | 租约到期后从已提交 step 恢复，副作用不重复 |

## 兼容与验收

- `REL-060`：`/api/v2/behavior/events` 及行为事件带可识别模式版本；同版本字段语义不得静默改变，
  破坏性变化使用新版本和迁移期。
- `REL-061`：基础设施可以替换，但接受、去重、追踪、保留、SLO 和降级语义必须保持。
- `REL-A01`：验证合法、重复、越权动作、过期、超前、缺少身份和结构无效事件的逐项结果。
- `REL-A02`：完成“推荐 → 曝光 → 后续动作 → 分析和特征”的链路，验证归因字段、时限和去重。
- `REL-A03`：注入 `REL-054` 矩阵中的每一行，验证规定响应、健康状态、指标和日志。未覆盖的行不得
  把本条标为已满足。
- `REL-A04`：验证各类数据在规定期限自动删除，关闭个性化后 24 小时内清除在线特征。
- `REL-A05`：以真实月度窗口和统一口径生成可用性、延迟、异步延迟、RPO 和 RTO 报告。合成数据不
  关闭本条。
