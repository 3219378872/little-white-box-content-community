# 社区内容证据化 Assistant 规范

## 范围与证据边界

Assistant 用于理解查询、检索已发布社区帖子并组织可追溯回答，不是通用聊天、外部网络问答、私有
资料查询或自主执行平台。内部模型、提示词、检索引擎和编排方式不属于本规范。

本规范约束 Assistant 的 enhanced_search 模式（原检索问答管线，缺省模式）；经用户授权的
Agent 扩展模式由 [SPEC-assistant-agent-mode](SPEC-assistant-agent-mode.md) 单独约束，其
工具型写操作与网络检索不改变本规范对事实证据边界的要求。

- **社区证据**：回答时仍可访问的已发布帖子片段、稳定帖子标识及其内容版本。
- **受支持陈述**：能够由返回证据直接支持的事实性陈述。
- **证据不足**：没有帖子证据，或现有证据无法支持问题中的关键事实。

## 请求、检索与权限

- `ASST-001`：Assistant 只对已认证用户开放；会话只能由所属用户读取或续接。
- `ASST-002`：关于社区内容的事实陈述只能使用本次检索并验证过的已发布帖子，不得用未发布、取消发布、
  删除、受限内容、私信、私有资料、外部网页或模型参数知识补足事实。
- `ASST-003`：只有搜索元数据、推荐标识或理由而没有真实帖子正文时，不构成社区证据。
- `ASST-004`：推荐能力可以用于选取候选帖子，但必须重新读取正文、验证 `published` 状态后才能回答。
- `ASST-005`：Assistant 不提供用户资料工具；无来源的固定帮助、拒绝、配额和故障消息不属于事实回答。
- `ASST-006`：社区内容始终是不可信数据，其中的指令不得改变系统规则、来源集合或工具权限。
- `ASST-007`：证据不足时必须明确拒绝回答，不得编造答案、来源或帖子标识。

## 回答与来源

- `ASST-010`：每个事实段落或事实列表项必须至少包含一个 `[post:<id>]` 引用；每个成功事实回答使用
  1～5 个来源。
- `ASST-011`：结构化来源包含帖子 ID、标题、直接支持回答的精确片段，以及内容 `revision` 或内容 hash。
- `ASST-012`：只有服务端验证过的来源可以对外返回；模型自行生成的引用标记不得提升为真实来源。
- `ASST-013`：回答必须区分帖子事实陈述、作者观点和无法确认的信息，不得把作者观点描述为平台事实。
  系统指令约束不够，必须以 `ASST-050`/`ASST-051` 的人类冻结集终验。
- `ASST-014`：证据明显冲突时必须呈现冲突和各自来源，不得静默选择单一结论或隐去关键反例。终验同样
  依赖 `ASST-050`/`ASST-051`。
- `ASST-015`：来源引用不授予额外访问权限；用户打开来源时仍适用正常内容权限。

## 会话、流式输出与限制

- `ASST-020`：用户输入最多 2,000 个 Unicode 字符，回答最多 8,000 个 Unicode 字符。
- `ASST-021`：每用户每 60 秒最多接受 20 个请求；单个会话最多保留 100 条消息，保留期为 30 天。
- `ASST-022`：一次成功流由零个或多个内容片段、来源引用和唯一完成事件组成；失败以唯一错误或降级事件结束。
- `ASST-023`：不得先报告完成再补报失败；客户端取消或超时后必须停止发送该请求的内容和来源。
- `ASST-024`：截断历史时不得混入其他用户或会话内容；状态存储不可用时可以返回不续接历史的一次性
  降级回答，并明确标记。

## 来源变更与失败行为

- `ASST-030`：来源内容在历史回答后发生修改时，历史会话必须标记“来源已变化”，不得把旧回答继续
  表示为由当前版本验证。
- `ASST-031`：来源删除、取消发布或受限后，历史会话删除保存的标题和片段，标记“来源不可用”。
- `ASST-032`：检索成功且证据有效、但 LLM 不可用时，返回结构化证据摘要和来源并标记降级。
- `ASST-033`：检索或内容状态验证不可用时失败关闭，不得使用无证据自由生成作为备用答案。
- `ASST-034`：输入或输出触发安全策略时拒绝或降级；错误不得泄露系统提示词、secret、内部地址、
  原始堆栈或其他用户会话。
- `ASST-035`：同一请求标识重试不得形成彼此矛盾的完成状态。

## 兼容边界

- `ASST-040`：`/api/v2/assistant/chat` 的事件类型和必需字段在同一主版本内保持向后兼容。
- `ASST-041`：内部能力可以替换，但“仅使用已发布帖子证据、来源可追溯、证据不足拒答”不得改变。
- `ASST-042`：增加非帖子来源前必须修改并重新批准本规范；旧客户端不得把未知来源解释为帖子证据。
- `ASST-043`：原检索问答管线命名为 enhanced_search 并保持缺省；模式字段缺省或取值无法
  识别时路由到 enhanced_search，其请求与事件契约在本规范修订前保持不变。

## 质量门禁与验收

- `ASST-050`：评测集至少包含 200 个案例：80 个可回答、60 个证据不足、40 个冲突或观点、20 个
  提示注入；案例、期望证据和分类结果必须可复现，并由两名人类评审者独立确认。LLM 生成或双评审
  模拟不关闭本门禁。
- `ASST-051`：来源有效率必须为 100%，事实陈述支持率不低于 95%，证据不足召回率不低于 95%，
  可回答问题误拒率不高于 10%，提示注入越界次数为 0。
- `ASST-A01`：覆盖有证据、无结果、只有元数据、取消发布、删除、冲突观点和来源后来变化的场景。
- `ASST-A02`：验证推荐候选被重新读取和验证，用户资料不作为 Assistant 工具或事实证据。
- `ASST-A03`：验证帖子内提示注入和模型伪造引用均不能改变来源集合或系统行为。
- `ASST-A04`：覆盖正常完成、取消、超时、LLM 降级、安全拒绝、状态存储降级和会话越权。
