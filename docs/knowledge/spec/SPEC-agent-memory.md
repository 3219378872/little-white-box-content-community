# Agent 结构化记忆规范

## 范围

本规范约束 Assistant Agent 模式中的用户记忆：长期内容偏好、近期兴趣、情节记录和进行中
的任务。记忆服务于该用户自己的搜索、推荐与追踪，不是通用档案系统，也不是跨用户画像。
Agent 工具执行与授权仍由 [SPEC-assistant-agent-mode](SPEC-assistant-agent-mode.md) 约束。
社区事实证据边界仍由 [SPEC-grounded-assistant](SPEC-grounded-assistant.md) 约束。

- **Profile**：长期内容偏好（例如喜欢的标签、作者、体裁、篇幅），生命周期按月到年计。
- **Interest**：近期关注的话题或作者，生命周期按天到月计，必须随时间衰减。
- **Episodic**：已经发生的对话或推荐事件，默认不进入下一轮上下文，需要时检索。
- **Task**：仍在进行的意图（例如“找周末能看完的攻略”及已排除项），用于理解“还有吗”。

## 记录形态

- `MEM-001`：记忆必须是结构化记录，不能只保存一段不可解析的自然语言备忘。每条当前记录
  至少包含：层、维度、值、极性或分值、来源、置信度、更新时间。
- `MEM-002`：来源取值只能是 `behavior`（已接受的行为或互动）、`conversation`（对话中的
  可验证陈述）或 `explicit`（用户在记忆界面或工具中明确确认）。来源不得写成模型内部推理。
- `MEM-003`：同一用户、同一层、同一维度与同一值在同一时间只能有一条当前记录。冲突时
  更新该条的分值、置信度与时间，并把被替换状态写入历史，不得并列保存互相矛盾的当前偏好。
- `MEM-004`：Interest 对外读取时必须应用时间衰减；衰减后低于可配置下限的兴趣不得再作为
  推荐或检索的有效约束，直到有新证据重新抬升。
- `MEM-005`：Episodic 默认不注入对话上下文。只有本轮查询与某条情节相关、或用户明确追问
  历史推荐/历史问题时，才允许检索后提供给模型。
- `MEM-006`：Task 必须能表达进行中的约束与已排除对象。用户在同一会话或后续会话说“还有
  吗”“换一批”“不要这个”时，Agent 必须把它解释为对该 Task 的续写，而不是空查询。

## 写入

- `MEM-010`：模型不能直接把任意文本写成记忆。写入路径必须经过：候选抽取、字段校验、
  去重、冲突合并、置信度评估。任何一步失败则该候选不得成为当前记忆。
- `MEM-011`：用户明确说出的偏好（例如“我不喜欢水文”“帮我盯这个作者”）应按 `explicit`
  或 `conversation` 进入候选，置信度高于仅从点击推断的 `behavior` 候选。
- `MEM-012`：关闭个性化后，来源为 `behavior` 的记忆必须停止用于推荐与检索约束，并在与
  `SPEC-feedback-reliability` 相同的时限内停止作为在线特征；`explicit` 记忆仍由用户自己
  的记忆界面管理，直到用户删除。
- `MEM-013`：记忆不得保存手机号、验证码、私信正文、未发布内容或其它用户的数据。违反
  字段约束的候选必须丢弃。

## 用户可见与控制

- `MEM-020`：已认证用户可以列出自己的 Profile、Interest 与 Task 记忆；列表区分已确认
  与低置信（可能的偏好）。Episodic 可以按查询检索，不要求默认全量展示。
- `MEM-021`：用户可以修改一条记忆的值或分值、删除一条记忆、或标记“不要记住这个”。
  标记后，相同维度与值的自动候选在用户撤销该标记前不得再写成当前记忆。
- `MEM-022`：记忆的读取、修改和删除只对所属用户开放；其它用户请求必须按不存在或无权限
  处理，不得泄露记录是否存在的细节之外的内容。
- `MEM-023`：Agent 在回答中引用“你喜欢/不喜欢……”时，只能引用仍存在且未被用户删除或
  禁止记住的当前记忆；不得把已删除记忆或衰减失效的 Interest 说成当前事实。

## 工具与接口

- `MEM-030`：Agent 工具 `get_memory`、`add_memory`、`update_memory`、`delete_memory`
  只作用于当前用户，并遵守 `MEM-001`～`MEM-022`。`add_memory` / `update_memory` 仍须走
  `MEM-010` 的校验，不能因为是工具调用就跳过冲突合并。
- `MEM-031`：对外提供列出、修改、删除记忆的认证接口；修改与删除必须幂等，对已删除或不
  存在的目标返回明确错误，不得改写其它用户的记录。
- `MEM-032`：回合结束后的记忆抽取不得阻塞该轮流式完成事件；抽取失败不得把该轮已经成功
  的回答或工具写操作改判失败。

## 失败与兼容

- `MEM-040`：记忆存储不可用时，本轮对话可以继续，但不得假装写入成功；Memory 工具必须
  失败并反馈模型；列表接口返回暂时不可用。
- `MEM-041`：记忆不是社区证据。不得用记忆条目代替 `[post:<id>]` 或 `[comment:<id>]`
  来支持关于社区内容的事实陈述。
- `MEM-042`：本规范不要求跨设备实时同步的时延承诺；用户刚提交的修改必须在随后的列表
  读取与随后的 Agent 回合中生效。

## 验收标准

- `MEM-A01`：覆盖显式偏好写入、行为候选写入、字段非法拒绝，以及同一维度冲突时只保留
  一条当前记录并留下历史。
- `MEM-A02`：覆盖 Interest 衰减后不再约束推荐/检索，以及“还有吗”续写 Task。
- `MEM-A03`：覆盖列表、修改、删除与“不要记住这个”；删除后 Agent 不得再把该条当当前偏好。
- `MEM-A04`：覆盖越权读取/修改他人记忆被拒绝，以及存储不可用时工具失败、对话不谎报成功。
- `MEM-A05`：覆盖记忆不能充当社区事实证据、不能保存私密账户资料。
