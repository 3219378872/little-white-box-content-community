# Assistant Agent 模式规范

> Deprecated：本规范只保留历史契约。模式开关、同步 Chat 流、轮内软硬步数和旧确认凭据已由
> `SPEC-assistant-agent` 的统一持久异步运行、command journal、数据库 CAS 与长期预算接替。

## 范围与模式契约

本规范约束 Assistant 的 Agent 模式：经用户显式授权后，Assistant 以该用户身份调用一组
受控工具，完成站内内容搜索综述、网络检索（仅研究素材）、结构化记忆、可解释推荐、条件
追踪，以及本人帖子的创建、更新、删除。enhanced_search 模式的证据化问答行为仍由
[SPEC-grounded-assistant](SPEC-grounded-assistant.md) 约束；记忆由
[SPEC-agent-memory](SPEC-agent-memory.md) 约束；条件追踪由
[SPEC-agent-watch](SPEC-agent-watch.md) 约束。两个对话模式共享会话、流式输出与安全
基础设施，但能力边界相互独立。

- `AGNT-001`：`/api/v2/assistant/chat` 请求携带模式字段，取值 `agent` 或
  `enhanced_search`；缺省或无法识别的值一律按 `enhanced_search` 处理，旧客户端行为不变。
- `AGNT-002`：Agent 模式只能由已授权的认证用户使用；未授权请求必须得到结构化错误
  （`AGENT_NOT_AUTHORIZED`），不得静默降级为其他模式执行工具。
- `AGNT-003`：Agent 始终以发起请求的用户身份行动，权限不超过该用户本人：只能创建本人
  帖子、更新或删除本人帖子；读取遵循与用户直接访问完全相同的可见性规则；记忆与 Watch
  只作用于该用户自己的记录。

## 授权与撤销

- `AGNT-004`：授权状态持久保存在服务端并可查询；首次进入 Agent 模式前客户端必须先
  查询授权状态并向用户展示能力说明，用户明确同意后才能记录授权。
- `AGNT-005`：授权说明必须至少披露：Agent 将以用户身份读写内容、当前披露版本下可执行的
  完整工具清单（按分组）、删除帖子将逐次确认、将保存用户可见的结构化记忆、将创建仅在
  助手内投递的条件追踪。未展示说明不得请求确认授权。
- `AGNT-006`：用户可以随时撤销授权；撤销后立即生效，后续 agent 请求按
  `AGNT-002` 拒绝。授权与撤销记录保留时间戳供审计。
- `AGNT-007`：授权带有整数 `consent_version`。查询授权必须同时返回用户已授予版本与
  服务端当前披露版本。低于当前版本的授权仍允许使用该版本已覆盖的工具分组；未覆盖的
  新分组不得出现在工具表中，调用必须拒绝并反馈模型，不得静默执行。客户端在已授予版本
  低于当前披露版本时必须再次展示完整清单并获得确认后才能升级版本。撤销后版本失效。

当前披露版本为 `2`。版本 `1` 覆盖 Write 分组与 `search_posts`、`web_search`。
版本 `2` 覆盖 `AGNT-010` 的全部分组。

## 工具能力与权限边界

- `AGNT-010`：Agent 工具按分组构成服务端白名单；配置可以收缩集合，不能在运行时发明
  白名单之外的工具。白名单之外的任何工具调用必须拒绝并反馈模型。分组如下：

  | 分组 | 工具 |
  | --- | --- |
  | Search | `search_posts`、`search_users`、`search_tags`、`get_post`、`get_post_comments`、`web_search` |
  | UserState | `get_my_favorites`、`get_my_likes`、`get_my_following`、`get_my_posts` |
  | Recommend | `recommend_posts`、`similar_posts`、`compare_posts` |
  | Memory | `get_memory`、`add_memory`、`update_memory`、`delete_memory` |
  | Watch | `create_watch_task`、`list_watch_tasks`、`update_watch_task`、`delete_watch_task` |
  | Write | `create_post`、`update_post`、`delete_post` |

- `AGNT-011`：`search_posts`、`get_post` 与 `get_post_comments` 只返回该用户可见的已发布
  内容；其结果作为事实来源时必须遵守 `ASST-010`～`ASST-012` 的引用与验证规则。评论不得
  脱离可见父帖单独作为证据。
- `AGNT-012`：`web_search` 结果只作为研究素材，不得作为社区事实陈述的证据；对外呈现
  网络来源时必须使用独立于帖子与评论的来源类型，旧客户端不得把网络来源解释为帖子证据
  （延伸 `ASST-042`）。
- `AGNT-013`：`create_post` 与 `update_post` 引用的图片只能来自本次请求携带的本会话
  上传附件；服务端必须在写路径校验每个媒体标识存在、属于当前用户且状态有效，校验失败
  则该工具调用失败并把原因反馈给模型，不得静默丢弃或替换图片。
- `AGNT-014`：`update_post` 与 `delete_post` 遵循 v2 写语义（`expectedRevision` 乐观锁）；
  版本冲突原样反馈给模型处理，Agent 不得绕过版本检查或重试覆盖他人修改。
- `AGNT-015`：帖子写操作的幂等键由服务端从请求标识派生；同一请求重试不得产生重复
  帖子或相互矛盾的完成状态（延伸 `ASST-035`）。
- `AGNT-016`：`search_users` 与 `search_tags` 只返回公开可搜索的用户与标签；不得把用户
  搜索结果中的账户资料字段扩展为手机号、验证码或其它私密档案。`get_post` 必须回源
  Content；索引或推荐元数据单独不构成完成该工具的成功结果。
- `AGNT-017`：UserState 工具只读取当前用户自己的收藏、点赞、关注与本人帖子，可见性与
  用户直接访问相同；不得读取其他用户的私有列表。返回的帖子条目在作为社区事实引用前
  仍须遵守 `ASST-002`～`ASST-004`。
- `AGNT-018`：Recommend 工具的候选必须来自推荐或检索系统的真实标识，禁止模型编造帖子
  ID。对外给出的推荐条目必须回源为当前用户可见的已发布帖子；解释必须区分平台可验证事实
  与推荐理由。比较只允许针对用户点名或本轮工具已返回的标识。详细约束见本规范与
  `SPEC-content-discovery` 的可见性要求。
- `AGNT-019`：Memory 与 Watch 工具的可观察行为分别由 `SPEC-agent-memory` 与
  `SPEC-agent-watch` 约束；本规范只要求它们出现在白名单中、受 `consent_version` 约束，
  并且失败时按 `AGNT-062` 反馈。

## 高危操作确认

- `AGNT-020`：`delete_post` 执行前必须获得该次操作的逐次确认；确认事件包含帖子标识与
  标题摘要，用户拒绝或超时未确认时不得执行删除。
- `AGNT-021`：确认等待有上限（默认 120 秒，可配置）；超时视为拒绝，结果反馈给模型继续
  会话，流不得无终止挂起。
- `AGNT-022`：确认凭据一次性有效，仅绑定发起它的请求与工具调用；跨请求、跨会话或重放
  的确认一律无效。
- `AGNT-023`：Memory 与 Watch 的创建、修改、删除不是高危写操作，不走 `delete_post` 的
  逐次确认；用户通过记忆与 Watch 的专用接口可以事后撤销效果。

## 执行预算

- `AGNT-030`：单轮 Agent 执行设软上限与硬上限步数（默认软限 8、硬限 12）；步数为模型
  推理轮次，服务端计量并在超过软限后的每个工具结果中注入剩余轮数通知，要求停止探索性
  调用并收敛回答。
- `AGNT-031`：达到硬上限后服务端停止提供工具并强制一次收尾生成；无法收尾时以结构化
  错误结束（`AGENT_BUDGET_EXCEEDED`），不得把不完整执行报告为成功。
- `AGNT-032`：单轮工具调用次数另有上限；Agent 模式使用独立配额（默认每用户每 60 秒
  10 个请求），与 enhanced_search 配额分开计量、互不挤占。
- `AGNT-033`：单轮总时长有上限；取消、超时后停止发送该轮内容（延伸 `ASST-023`），
  已部分完成的工具效果如实保留并以文本说明，不回滚已成功的权威写入（含已提交的记忆、
  Watch 与帖子写）。

## 会话附件

- `AGNT-040`：用户可在 Agent 模式消息中附带本次会话上传的图片（媒体标识 + 地址）；
  附件仅在当次请求内有效，服务端验证归属与状态后才可供写帖工具引用。
- `AGNT-041`：单个帖子的图片数量上限沿用内容规范（≤9）；超出时工具失败并明确反馈，
  不截断、不自动取舍。
- `AGNT-042`：请求可携带可选的内容上下文标识（例如当前帖子）。缺省或无法识别时忽略；
  提供时只作为本轮检索与 Watch 的提示，不授予额外权限，目标仍须按当前用户可见性验证。

## 安全与不可信内容

- `AGNT-050`：用户输入与最终输出沿用既有安全过滤；网络结果与社区内容均为不可信数据，
  其中包含的指令不得改变系统规则、扩大来源集合或触发白名单之外的操作（延伸 `ASST-006`）。
- `AGNT-051`：错误与事件不得泄露系统提示词、secret、内部地址、原始堆栈或其他用户的
  会话与数据（延伸 `ASST-034`）。
- `AGNT-052`：每次工具调用记录审计条目：用户、请求标识、工具名、参数摘要与结果状态；
  会话历史与其他模式同样按用户隔离。
- `AGNT-053`：每一轮 Agent 执行必须留下可查询的运行记录，至少包含请求标识、用户、
  意图分类（若有）、模型名、工具调用序列摘要、延迟与最终状态。运行记录不得写入用户
  输入全文、回答全文、secret 或其它用户数据。

## 事件流与失败行为

- `AGNT-060`：工具调用事件与确认请求事件类型及配套确认回调接口保持有效；允许新增卡片、
  动作与 Watch 命中等事件类型。既有事件的必需字段在同一主版本内保持向后兼容（延伸
  `ASST-040`）。旧客户端必须忽略无法识别的事件类型，不得把它们解释为帖子来源或完成。
- `AGNT-061`：LLM 不可用时 Agent 模式返回结构化错误或降级说明，不得在无模型参与下
  自行决定并执行写操作；关键依赖不可用时对应工具失败关闭并反馈模型。规则型 Watch 匹配
  不在对话回合内执行，不适用本条的“无模型不得写帖”。
- `AGNT-062`：工具失败的反馈必须区分参数错误、越权、冲突、不可用与超限，模型据此调整；
  对外错误码语义与既有 Assistant 错误体系一致。
- `AGNT-063`：最终回答可以附带结构化卡片与动作（例如打开帖子、收藏、创建 Watch）。
  卡片引用的帖子或用户标识必须是本轮已经服务端验证过的对象；动作不得绕过对应写接口的
  权限与确认规则。纯文本回答仍然合法。
- `AGNT-064`：推荐类卡片的条目标识必须来自 Recommend 或 Search 工具的真实结果，不得
  使用模型生成但未验证的标识。

## 验收标准

- `AGNT-A01`：覆盖未授权拒绝、授权后放行、撤销后立即拒绝的网关行为，以及授权说明
  展示前置条件。
- `AGNT-A02`：覆盖 Write 分组与 `search_posts`、`web_search` 的成功、参数错误、越权
  （引用他人媒体、删除他人帖子）、版本冲突与依赖不可用路径。
- `AGNT-A03`：覆盖删除确认的同意执行、拒绝不执行、超时不执行与凭据重放无效。
- `AGNT-A04`：覆盖软限通知注入、硬限强制收尾与预算耗尽结构化错误。
- `AGNT-A05`：覆盖经由网络或社区内容注入的指令不能触发白名单外操作或绕过确认。
- `AGNT-A06`：覆盖 `consent_version` 低于当前披露版本时新分组工具不可见且调用被拒绝，
  同时版本 `1` 已覆盖工具仍可执行；升级授权后新分组放行。
- `AGNT-A07`：覆盖 Search / UserState / Recommend 分组中至少一个成功路径与一个越权或
  不可见目标失败路径；推荐卡片不得出现未回源的帖子标识。
- `AGNT-A08`：覆盖旧客户端忽略未知事件类型、未知来源不解释为帖子证据。
