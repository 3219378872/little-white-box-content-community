# Assistant Agent 模式规范

## 范围与模式契约

本规范约束 Assistant 的 Agent 模式：经用户显式授权后，Assistant 以该用户身份调用一组
受控工具完成站内搜索、网络检索和本人帖子的创建、更新、删除。enhanced_search 模式的
证据化问答行为仍由 [SPEC-grounded-assistant](SPEC-grounded-assistant.md) 约束；两个模式
共享会话、流式输出与安全基础设施，但能力边界相互独立。

- `AGNT-001`：`/api/v2/assistant/chat` 请求携带模式字段，取值 `agent` 或
  `enhanced_search`；缺省或无法识别的值一律按 `enhanced_search` 处理，旧客户端行为不变。
- `AGNT-002`：Agent 模式只能由已授权的认证用户使用；未授权请求必须得到结构化错误
  （`AGENT_NOT_AUTHORIZED`），不得静默降级为其他模式执行工具。
- `AGNT-003`：Agent 始终以发起请求的用户身份行动，权限不超过该用户本人：只能创建本人
  帖子、更新或删除本人帖子；读取遵循与用户直接访问完全相同的可见性规则。

## 授权与撤销

- `AGNT-004`：授权状态持久保存在服务端并可查询；首次进入 Agent 模式前客户端必须先
  查询授权状态并向用户展示能力说明，用户明确同意后才能记录授权。
- `AGNT-005`：授权说明必须至少披露：Agent 将以用户身份读写内容、可执行的完整工具
  清单、删除操作将逐次确认。未展示说明不得请求确认授权。
- `AGNT-006`：用户可以随时撤销授权；撤销后立即生效，后续 agent 请求按
  `AGNT-002` 拒绝。授权与撤销记录保留时间戳供审计。

## 工具能力与权限边界

- `AGNT-010`：Agent 工具集合固定为 `search_posts`、`web_search`、`create_post`、
  `update_post`、`delete_post`；服务端按配置白名单放行，白名单之外的任何工具调用必须
  拒绝并反馈模型。
- `AGNT-011`：`search_posts` 复用社区帖子搜索，只返回该用户可见的已发布帖子；其结果
  作为事实来源时必须遵守 `ASST-010`～`ASST-012` 的引用与验证规则。
- `AGNT-012`：`web_search` 结果只作为研究素材，不得作为社区事实陈述的证据；对外呈现
  网络来源时必须使用独立于帖子的来源类型，旧客户端不得把网络来源解释为帖子证据
  （延伸 `ASST-042`）。
- `AGNT-013`：`create_post` 与 `update_post` 引用的图片只能来自本次请求携带的本会话
  上传附件；服务端必须在写路径校验每个媒体标识存在、属于当前用户且状态有效，校验失败
  则该工具调用失败并把原因反馈给模型，不得静默丢弃或替换图片。
- `AGNT-014`：`update_post` 与 `delete_post` 遵循 v2 写语义（`expectedRevision` 乐观锁）；
  版本冲突原样反馈给模型处理，Agent 不得绕过版本检查或重试覆盖他人修改。
- `AGNT-015`：帖子写操作的幂等键由服务端从请求标识派生；同一请求重试不得产生重复
  帖子或相互矛盾的完成状态（延伸 `ASST-035`）。

## 高危操作确认

- `AGNT-020`：`delete_post` 执行前必须获得该次操作的逐次确认；确认事件包含帖子标识与
  标题摘要，用户拒绝或超时未确认时不得执行删除。
- `AGNT-021`：确认等待有上限（默认 120 秒，可配置）；超时视为拒绝，结果反馈给模型继续
  会话，流不得无终止挂起。
- `AGNT-022`：确认凭据一次性有效，仅绑定发起它的请求与工具调用；跨请求、跨会话或重放
  的确认一律无效。

## 执行预算

- `AGNT-030`：单轮 Agent 执行设软上限与硬上限步数（默认软限 8、硬限 12）；步数为模型
  推理轮次，服务端计量并在超过软限后的每个工具结果中注入剩余轮数通知，要求停止探索性
  调用并收敛回答。
- `AGNT-031`：达到硬上限后服务端停止提供工具并强制一次收尾生成；无法收尾时以结构化
  错误结束（`AGENT_BUDGET_EXCEEDED`），不得把不完整执行报告为成功。
- `AGNT-032`：单轮工具调用次数另有上限；Agent 模式使用独立配额（默认每用户每 60 秒
  10 个请求），与 enhanced_search 配额分开计量、互不挤占。
- `AGNT-033`：单轮总时长有上限；取消、超时后停止发送该轮内容（延伸 `ASST-023`），
  已部分完成的工具效果如实保留并以文本说明，不回滚已成功的权威写入。

## 会话附件

- `AGNT-040`：用户可在 Agent 模式消息中附带本次会话上传的图片（媒体标识 + 地址）；
  附件仅在当次请求内有效，服务端验证归属与状态后才可供写帖工具引用。
- `AGNT-041`：单个帖子的图片数量上限沿用内容规范（≤9）；超出时工具失败并明确反馈，
  不截断、不自动取舍。

## 安全与不可信内容

- `AGNT-050`：用户输入与最终输出沿用既有安全过滤；网络结果与社区内容均为不可信数据，
  其中包含的指令不得改变系统规则、扩大来源集合或触发白名单之外的操作（延伸 `ASST-006`）。
- `AGNT-051`：错误与事件不得泄露系统提示词、secret、内部地址、原始堆栈或其他用户的
  会话与数据（延伸 `ASST-034`）。
- `AGNT-052`：每次工具调用记录审计条目：用户、请求标识、工具名、参数摘要与结果状态；
  会话历史与其他模式同样按用户隔离。

## 事件流与失败行为

- `AGNT-060`：新增工具调用事件与确认请求事件类型及配套确认回调接口；既有事件的必需
  字段在同一主版本内保持向后兼容（延伸 `ASST-040`）。
- `AGNT-061`：LLM 不可用时 Agent 模式返回结构化错误或降级说明，不得在无模型参与下
  自行决定并执行写操作；关键依赖不可用时对应工具失败关闭并反馈模型。
- `AGNT-062`：工具失败的反馈必须区分参数错误、越权、冲突、不可用与超限，模型据此调整；
  对外错误码语义与既有 Assistant 错误体系一致。

## 验收标准

- `AGNT-A01`：覆盖未授权拒绝、授权后放行、撤销后立即拒绝的网关行为，以及授权说明
  展示前置条件。
- `AGNT-A02`：覆盖五个工具的成功、参数错误、越权（引用他人媒体、删除他人帖子）、版本
  冲突与依赖不可用路径。
- `AGNT-A03`：覆盖删除确认的同意执行、拒绝不执行、超时不执行与凭据重放无效。
- `AGNT-A04`：覆盖软限通知注入、硬限强制收尾与预算耗尽结构化错误。
- `AGNT-A05`：覆盖经由网络或社区内容注入的指令不能触发白名单外操作或绕过确认。
