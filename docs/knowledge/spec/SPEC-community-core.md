# 社区核心能力规范

## 范围

本规范定义身份、资料、内容生命周期、评论、点赞、收藏、关注、媒体和一对一私信的可观察行为。
账户注销、内容申诉、管理后台、群聊、消息撤回、消息删除，以及点赞/评论/关注的站内通知中心
不在当前范围。关注流、搜索和推荐由 `SPEC-content-discovery` 约束，Assistant 由
`SPEC-assistant-agent` 约束。

## 术语与访问边界

- **已认证用户**：后端能够验证身份且凭证未失效的用户。
- **已发布内容**：处于 `published` 状态、允许普通用户访问的社区内容。
- **不可用内容**：草稿、已删除、受限或当前访问者无权查看的内容。
- 已发布帖子、评论、公开资料、搜索和冷启动推荐允许匿名读取；写操作、关注流、私信和 Assistant
  必须由已认证用户调用。
- 未认证或上下文中缺少有效调用者身份时，受保护写操作必须返回未认证，不得返回系统错误。

## 身份与权限

- `CORE-001`：写操作必须验证调用者，未认证请求不得以其他用户身份执行操作。
- `CORE-002`：用户只能修改、取消发布或删除自己拥有的内容，除非另有已批准的管理规范。
- `CORE-003`：只有会话参与者可以读取私信、会话和未读状态；资源标识不得绕过权限。
- `CORE-004`：注册、登录和资料维护属于当前能力；账户注销、申诉和管理操作不属于当前能力。
- `CORE-005`：不同用户访问同一资源时，必须按照资源状态和访问权限返回一致的可见性结果。

## 内容生命周期

- `CORE-010`：内容可以在 `draft` 与 `published` 间双向转换，且两种状态都可以进入 `deleted`；
  取消发布是 `published → draft`，`draft → deleted` 与 `published → deleted` 均为合法删除，`deleted` 是终态。
- `CORE-011`：创建内容时可以保存草稿或直接发布，并返回稳定内容标识、当前状态和单调递增的 `revision`。
- `CORE-012`：草稿仅作者可读；内容只有处于 `published` 时才可进入普通读取、公开列表、发现能力和
  Assistant 证据。
- `CORE-013`：发布、取消发布、编辑和删除必须携带调用者最后读取的预期 `revision`；版本冲突返回
  `409 Conflict`，不得覆盖并发更新。缺失或为 0 的预期 `revision` 视为参数错误，不得跳过冲突检测。
- `CORE-014`：成功变更内容后，后续读取必须返回新状态和新 `revision`；失败变更不得产生半完成公开状态。
- `CORE-015`：取消发布或删除后，内容不得作为条目出现在新的普通读取、公开列表、发现结果或
  Assistant 回答中。列表的 `Total` 允许按当前页过滤回减，不要求对全库做精确重算；客户端不得把
  `Total` 解释为仍包含不可用内容的遍历保证。
- `CORE-016`：匿名用户和非作者读取草稿、已删除或无权访问内容时统一返回不存在，不泄露历史状态。

## 输入边界与媒体

- `CORE-020`：帖子标题为 1～120 个 Unicode 字符，正文为 1～20,000 个 Unicode 字符。
- `CORE-021`：每个帖子最多包含 9 张图片和 10 个标签；每个标签为 1～32 个 Unicode 字符。
- `CORE-022`：评论正文为 1～2,000 个 Unicode 字符，只能附着在当前可互动的已发布内容上。
- `CORE-023`：图片仅支持 JPEG、PNG 和 WebP，按实际文件内容识别，单文件不得超过 10 MiB；
  宽、高任一边不得超过 8,192 px，解码后像素总数不得超过 25,000,000。服务必须在完整像素解码前
  读取图片头并拒绝超限输入。超过字节或像素上限与非法 multipart/缺少文件必须返回可区分结果，
  不得把所有解析失败一律当成文件过大。
- `CORE-024`：媒体上传成功后返回稳定媒体标识；帖子或消息只能引用调用者有权使用且上传完成的媒体。

## 互动与关系

- `CORE-030`：点赞、收藏、关注及其取消操作表示目标状态，重复请求返回相同最终状态，不重复累计关系或计数。
- `CORE-031`：同一用户、目标和互动类型在任一时刻最多存在一个有效关系。
- `CORE-032`：互动状态在写入成功后立即可查询。已认证访问者读取已发布帖子详情或列表时，响应必须
  包含该访问者对该帖的点赞和收藏状态；匿名访问者这些字段为未互动。公开计数允许最终一致，但必须
  在 30 秒内收敛。
- `CORE-033`：取消互动后，查询不得继续报告该关系有效；失败操作不得返回成功状态。
- `CORE-034`：点赞和收藏只能作用于当前可互动的已发布内容。对不存在或不可用目标必须统一返回不存在，
  不得据此泄露草稿或已删除内容。内容权威不可用时该写操作失败关闭。关注的目标是用户资料，不适用本条。

## 用户交流

- `CORE-040`：当前交流能力是一对一私信，支持文本、图片、视频和语音类型；不支持群聊、撤回、删除，
  以及点赞/评论/关注的站内通知中心。
- `CORE-041`：文本消息正文为 1～1,000 个 Unicode 字符；媒体消息必须引用已成功上传的媒体标识。
- `CORE-042`：消息发送必须带调用者生成、在发送者范围内唯一且最长 128 字符的幂等键。同一键和相同
  命令重复提交返回原消息标识；同一键绑定不同命令返回冲突。
- `CORE-043`：标记已读只影响当前用户在目标会话中的状态，不改变其他参与者的未读状态。
- `CORE-044`：私信发送以权威写入完成为成功。站内通知或推送若存在，只是派生效果，失败不得把已成功
  的发送改成可重试失败；当前产品不承诺赞/评/关通知投递。

## 写入、失败和一致性

- `CORE-050`：创建帖子、评论和媒体必须接受客户端幂等键；同一调用者使用同一键重试不得产生重复资源。
- `CORE-051`：参数无效、未认证、无权限、不存在、版本冲突、幂等冲突、限流和暂时不可用必须形成
  可区分的业务结果。
- `CORE-052`：后端无法确认权威写入完成时不得返回成功，响应必须让客户端判断是否可以安全重试。
- `CORE-053`：权威写入已经提交时，缓存失效、索引、通知或其他异步效果失败不得把响应改成可重试失败；
  系统应返回业务成功并通过可靠异步处理、重试和告警恢复派生效果。
- `CORE-054`：失败响应不得暴露 secret、内部堆栈、数据库结构、内部服务地址或未消毒的底层 `error`
  字符串。未知错误使用通用系统错误文案。

## 分页与兼容

- `CORE-060`：页码列表保证单页内不重复；并发创建、删除或排序变化可能导致跨页移动，不承诺遍历快照。
- `CORE-061`：关注流和推荐的同一游标链必须遵循 `SPEC-content-discovery` 的不重复和上下文绑定要求。
- `CORE-062`：2026-08-13 已批准移除 `/api/v1` 帖子写接口（创建/更新/删除）；帖子写路径仅为
  `/api/v2/post*`，并强制 `CORE-013`。其余已发布的 `/api/v1` 社区核心读/互动/用户契约和
  `/api/v2/messages*` 在同一主版本内保持字段和语义向后兼容；此后破坏性变化必须使用新版本或
  先修改本规范。
- `CORE-063`：客户端不得依赖内部服务数量、存储结构或异步处理方式；新增可选字段不得改变旧客户端
  对既有成功和失败状态的解释。

## 验收标准

- `CORE-A01`：覆盖 `draft ⇄ published`、`draft → deleted`、`published → deleted`、删除后的非法转换、
  非作者访问和 revision 冲突。
- `CORE-A02`：验证匿名读取已发布内容，草稿和删除内容对非作者统一不可见。
- `CORE-A03`：验证标题、正文、评论、图片和标签的上下边界及越界失败；验证上传超过 10 MiB、
  单边超过 8,192 px、总像素超过 25,000,000 与非法 multipart 返回对应业务结果，并证明像素预算在
  完整解码前生效。
- `CORE-A04`：重复执行创建、互动和消息命令，验证相同幂等键收敛、冲突键被拒绝、计数不重复。
- `CORE-A05`：验证会话参与者读取和标记已读，非参与者始终被拒绝。
- `CORE-A06`：注入权威写入失败与提交后派生效果失败，验证前者不返回成功、后者不诱导重复写入。
- `CORE-A07`：已认证用户对已发布帖子点赞后，详情与列表立即报告已赞；对草稿或不存在目标点赞返回
  不存在且不泄露状态。
