# 社区核心能力规范

## 范围

本规范定义用户创建、发布、互动和交流时可以观察到的后端行为，包括用户身份、内容生命周期、
评论与反应、关注关系和私信。不规定服务拆分、数据存储、消息系统或客户端界面。

关注流、搜索和推荐由 `SPEC-content-discovery` 约束；Assistant 由
`SPEC-grounded-assistant` 约束。

## 术语

- **已认证用户**：后端能够验证身份且请求未失效的用户。
- **已发布内容**：作者已完成发布、允许普通用户访问的社区内容。
- **不可用内容**：未发布、已删除、被限制或当前访问者无权查看的内容。
- **互动状态**：评论、点赞、收藏或关注等由用户主动产生且可查询的状态。

## 可观察行为

### 身份与权限

- `CORE-001`：需要用户身份的写操作必须验证调用者；未认证请求不得以其他用户身份执行操作。
- `CORE-002`：用户只能修改或删除自己拥有的资源，除非另有经批准的管理规范。
- `CORE-003`：不同用户访问同一资源时，后端必须按照资源状态和访问权限返回一致的可见性结果。

### 内容生命周期

- `CORE-010`：已认证用户可以创建内容，并获得可用于后续查询的稳定内容标识和明确状态。
- `CORE-011`：内容只有进入已发布状态后，才可以被普通用户、公开列表、发现能力和 Assistant 使用。
- `CORE-012`：作者成功更新内容后，后续读取必须返回新版本；失败更新不得产生对外可见的半完成状态。
- `CORE-013`：内容删除或变为不可用后，不得继续出现在普通读取、公开列表、发现结果或新的
  Assistant 证据中。
- `CORE-014`：内容列表的翻页结果不得在同一次遍历中无故重复；列表项必须能够解析到对应内容。

### 互动与关系

- `CORE-020`：已认证用户可以对可互动内容创建和删除评论；无权访问的内容不得接受互动。
- `CORE-021`：点赞、收藏和关注必须表示明确的最终状态；相同请求重试不得累计出重复关系。
- `CORE-022`：互动成功后，对应状态和公开计数必须最终一致；失败操作不得返回成功状态。
- `CORE-023`：取消点赞、收藏或关注后，查询结果不得继续把该关系报告为有效。

### 用户交流

- `CORE-030`：已认证用户可以向允许交流的目标用户发送私信，并在会话中查询已成功发送的消息。
- `CORE-031`：只有会话参与者可以读取会话、消息和未读状态；无关用户不得通过标识猜测获得内容。
- `CORE-032`：标记已读必须只影响当前用户在目标会话中的状态，不得改变其他参与者的未读状态。
- `CORE-033`：同一发送请求因网络原因重试时，不得向接收方生成多条业务上等价的消息。

## 失败行为

- `CORE-040`：参数无效、未认证、无权限、资源不存在和服务暂时不可用必须形成可区分的业务结果。
- `CORE-041`：失败响应不得暴露 secret、内部堆栈、数据库结构或内部服务地址。
- `CORE-042`：后端无法确认写操作完成时，不得把结果报告为成功；客户端必须能够判断是否可安全重试。
- `CORE-043`：单个下游能力故障不得使无关的公开读取返回伪造数据或错误成功状态。

## 兼容边界

- `CORE-050`：已发布的 `/api/v1` 社区核心契约和 `/api/v2/messages*` 消息契约在同一主版本内保持
  字段和语义向后兼容；破坏性变化必须通过新版本或明确迁移期提供。
- `CORE-051`：客户端只能依赖公开契约和业务结果，不得依赖内部服务数量、存储结构或异步处理方式。
- `CORE-052`：新增可选字段不得改变旧客户端对既有成功和失败状态的解释。

## 验收标准

- `CORE-A01`：覆盖创建、发布、读取、更新、删除的完整内容生命周期，并验证不可用内容不再公开。
- `CORE-A02`：覆盖作者与非作者的修改、删除和互动权限，包括至少一个未认证失败路径。
- `CORE-A03`：对点赞、收藏、关注和消息发送执行重复请求，验证最终状态唯一且计数不重复。
- `CORE-A04`：验证会话参与者可以读取和标记已读，非参与者始终被拒绝。
- `CORE-A05`：注入一个写入失败和一个下游不可用场景，验证没有错误成功、半完成公开状态或内部信息泄漏。

## 待人类确认

以下问题不构成本草案要求：

- 内容是否需要“草稿、审核、发布、限制、删除”以外的正式状态及其转换权限。
- 交流能力是否只包含一对一私信，是否需要拉黑、群聊、撤回或消息删除。
- 用户注销、内容申诉、管理操作和数据导出是否属于本意图的产品范围。
