# 观察到的缺口

- 当前没有广告、广告主、审核、角色或管理能力。[意图](../intent/INT-content-community-backend.md)把
  「管理后台、账户注销、申诉或内容审核工作流」列为非目标；[社区核心规格](../spec/SPEC-community-core.md)
  的范围排除内容申诉与管理后台，`CORE-004` 排除管理操作。
- 代码里只有未使用的骨架：`report` 表、帖子状态注释 `3:审核中`、没有调用方的 `SendNotification` RPC。
  JWT 只携带 `userId/username/tokenType`，没有角色。
- 媒体桶为 public-read，上传后即可经公开地址访问。推荐流条目要求完整帖子载荷，现有前端遇到非帖子条目
  会整页失败。

前端对应提案：前端仓 proposals 目录下的 `PROP-sponsored-ads-client`。

# 人类已决定（2026-10-01，当前对话）

1. 审核对象为付费广告。审核能力做成按业务类型接入的通用平台，首批业务是广告主资质与广告素材。
2. 做完整投放闭环：推荐流广告卡片、广告主控制台与审核工作台（Flutter 界面见前端提案）。
3. 机审参考 TikTok [Filter-And-Refine](https://arxiv.org/html/2507.17204v1) 的 Router → Ranker 级联
   工程架构；算法模型只保留接缝与占位实现。
4. 匿名用户的广告频控按会话计数，不跨会话。
5. 已过审广告被编辑后，新版本审核期间继续投放最近一次过审快照。
6. 周期一个月以上，分期交付。

# 建议的意图变更（INT-content-community-backend）

- 范围新增：
  - 付费广告：广告主与行业资质、广告创建与送审、先审后投、按市场政策的分级机审与人工审核、推荐流中
    带标识的广告投放、投后复审、举报与申诉。
  - 面向广告主的广告管理，以及面向审核人员的审核工作台；审核平台按业务类型接入。
- 非目标改为：
  - 社区内容（帖子、评论、私信、用户）的管理后台与审核工作流、账户注销及其申诉。广告审核与广告申诉
    不在此列。
  - 广告竞价、计费、预算扣减、结算、第三方广告网络与跨站追踪。
  - 未经人类标注评估就宣称机审准确率、自动化率或漏放率改善。
- 成功标准新增：未过审、已下线或资质失效的广告不得曝光；用户能识别广告及其广告主；广告主能看到可理解
  的拒绝原因并申诉；任一机审组件故障只会让结论更保守。

# 建议的规格

意图批准后，新建 `SPEC-review-platform`（前缀 `RVW`）与 `SPEC-sponsored-ads`（前缀 `ADS`），并修订
既有规格。下列编号均为拟议，批准时可以调整。

## SPEC-review-platform

送审与快照：

- `RVW-001`：审核对象以（业务类型，对象标识，revision）唯一识别；重复送审只产生一个审核任务。
- `RVW-002`：送审时冻结快照，包含文案、落地页、素材内容哈希、市场、行业与广告主；审核与结论只针对
  该快照，快照不可修改。
- `RVW-003`：对象产生新 revision 后，旧 revision 的未决任务作废；对作废任务的提交返回可区分结果。
  已作出的旧结论只保留审计，不改变对象状态。
- `RVW-004`：结论包含通过或拒绝、政策码、政策版本、决策来源（机器或人工）与时间；拒绝至少带一个政策码。

机审：

- `RVW-010`：机审依次执行指纹复用、硬规则、召回（Router）、精排（Ranker）和决策。召回阶段放行本身
  不构成通过依据。
- `RVW-011`：召回不可用时可以对全部 issue 执行精排；精排或其他组件超时、不可用或返回无效结果时转人审。
  任何降级路径都不得放宽自动通过条件，结论记录降级原因与组件版本。
- `RVW-012`：自动通过必须同时满足：未命中硬规则；全部召回候选的精排分数低于该（issue，市场）的通过
  阈值；该市场与行业允许自动通过；广告主已过首次送审保护期。
- `RVW-013`：自动拒绝仅限命中硬规则，或该（issue，市场）允许自动拒绝且分数不低于拒绝阈值。
- `RVW-014`：自动通过的对象按可配置比例抽样进入人工质检，用于估计漏放率；质检判定违规时对象下线并复审。
- `RVW-015`：指纹复用只在快照内容哈希、市场与政策版本完全一致时生效。
- `RVW-016`：阈值、规则、种子库与模型版本可以先以影子方式运行；影子结果不得改变任何结论或对象状态。
- `RVW-017`：每个机审阶段记录组件版本、耗时与输出，使同一快照能在指定版本下复现决策。
- `RVW-018`：模型组件允许是占位实现；占位结果必须能从版本中辨识，不得据此宣称机审效果。

人审：

- `RVW-020`：人审采用领取制。同一任务同一时刻最多由一名审核员持有，持有有期限且可续期，过期后可由
  他人领取。
- `RVW-021`：提交结论必须对应提交者当前有效的持有；持有已过期或已被他人接手时，提交被拒绝。
- `RVW-022`：审核员只能领取其市场与语言授权范围内的任务；队列按优先级与时限排序。
- `RVW-023`：人审界面展示快照、机审证据（命中规则、相似种子、分数）与政策定义；资质证件只对具备资质
  审核权限的审核员可见。
- `RVW-024`：质检复审与申诉必须由不同于原决策人的审核员处理。
- `RVW-025`：领取、续期、放弃、提交，以及种子、规则、阈值的变更，均写入只追加的审计记录。

种子库：

- `RVW-030`：确认违规的样本只能成为候选种子，经具备权限的第二人确认后才生效；种子停用后，新任务不再
  命中该种子。

一致性与权限：

- `RVW-040`：结论与其对外事件在同一权威事务内提交；重复或乱序投递不得让对象应用旧 revision 的结论。
- `RVW-041`：已送审但在约定时间内仍没有审核任务的对象必须被检测并补送，不得静默停留在审核中。
- `RVW-050`：审核写操作需要服务端校验的角色（审核员、质检、政策管理员）；角色撤销立即生效，不依赖
  访问令牌过期。
- `RVW-051`：结论只能经审核平台生效，业务方不提供绕过审核、直接置为通过的接口。

观测与验收：

- `RVW-060`：可观察送审到结论的耗时（分机审与人审）、机审自动化率、人审积压与最老任务年龄、质检
  不一致率、申诉改判率、指纹复用命中率，以及各组件的降级次数。
- `RVW-A01`：覆盖重复送审、审核中修改导致旧任务作废、结论乱序投递。
- `RVW-A02`：注入 Router 与 Ranker 超时和不可用，验证结论不放宽、版本标明降级。
- `RVW-A03`：两名审核员竞争领取，以及持有过期后被接手，验证旧持有者的提交被拒。
- `RVW-A04`：影子版本运行不改变结论；指纹复用只在三项一致时命中。
- `RVW-A05`：质检与申诉换人处理；角色撤销后的下一次请求即被拒绝。

## SPEC-sponsored-ads

广告主与广告：

- `ADS-001`：已认证用户可以申请成为广告主；受监管行业需要该市场有效的行业资质，资质审核通过后才能为
  该行业送审广告。
- `ADS-002`：资质过期或被撤销时，依赖该资质的在投广告停止投放。
- `ADS-010`：广告最新 revision 的审核状态为 `draft`、`pending_review`、`approved`、`rejected`、
  `appealing` 之一。投放资格独立判断：存在过审快照、未被下线（`offline`）、资质有效且在投放期内。
- `ADS-011`：编辑广告会产生新 revision 并送审。已过审广告在新版本审核期间继续投放最近一次过审快照，
  新版本通过后切换；新版本被拒时继续投放旧快照，除非资质失效或广告已被下线。
- `ADS-012`：投放的文案、素材、落地页与广告主名称只能来自过审快照。
- `ADS-013`：广告写操作沿用 `CORE-013` 的 revision 冲突检测与 `CORE-050` 的幂等键。
- `ADS-014`：拒绝与下线原因以可本地化的政策码告知广告主；每个被拒或被下线的 revision 可申诉一次。
- `ADS-015`：未过审素材不得经公开地址访问；过审后发布的素材按内容寻址，不可被覆盖。

投放：

- `ADS-020`：推荐流以独立的可选字段返回广告槽位，广告不进入帖子条目；帖子条目、位置、游标与去重语义
  保持 [内容发现规格](../spec/SPEC-content-discovery.md)不变。
- `ADS-021`：只在请求显式声明支持广告槽位时返回广告；未声明的客户端得到与当前一致的响应。
- `ADS-022`：广告服务失败、超时或无法确认广告资格时，返回不含广告的正常推荐结果。
- `ADS-023`：每个广告槽位包含广告标识、广告主名称，以及「为什么看到这条广告」的主要参数（市场、场景、
  是否个性化）。
- `ADS-024`：同一身份对同一广告每个 UTC 自然日的下发次数有上限；已认证用户按用户计数，匿名用户按会话
  计数，不跨会话。
- `ADS-025`：关闭个性化的用户与匿名用户只获得非个性化广告。
- `ADS-026`：用户隐藏或举报的广告在约定期限内不再向该用户投放。
- `ADS-027`：广告的曝光、点击使用独立的目标类型；同一（请求，目标类型，目标）最多记录一次曝光。广告
  事件不得进入帖子推荐特征、训练数据或帖子曝光去重。

投后：

- `ADS-030`：用户可以举报广告；举报生成投后复审任务，举报越多优先级越高。
- `ADS-031`：政策版本或生效种子库变更后，在投广告按新版本重新机审；判定违规的进入人审。
- `ADS-032`：下线在约定时间内对所有新请求生效。

权限、范围与观测：

- `ADS-040`：广告主只能读写自己的资料、资质与广告；资质证件只对本人与具备资质审核权限的审核员可见。
- `ADS-041`：不提供竞价、计费、预算扣减与结算；广告选择使用可解释的规则。
- `ADS-050`：可观察广告下发、曝光、点击、点击率、频控拦截、广告服务降级次数与下线传播延迟。
- `ADS-A01`：分别以未声明和已声明广告能力的请求读取推荐流；前者响应不变，后者获得带标识的广告槽位。
- `ADS-A02`：覆盖编辑已过审广告后：审核期间投旧快照、新版本通过后切换、新版本被拒仍投旧快照、资质失效
  即停投。
- `ADS-A03`：注入广告服务超时与失败，推荐流仍然成功且不含广告。
- `ADS-A04`：频控分别在用户与匿名会话下生效，匿名计数不跨会话。
- `ADS-A05`：广告曝光与点击不改变帖子推荐特征，也不影响帖子曝光去重。
- `ADS-A06`：未过审素材的公开地址不可访问。

## 既有规格修订

- `CORE-004` 与社区核心规格的范围：把「申诉和管理操作」限定为社区内容；广告审核、广告申诉与广告主管理
  由上述两份规格约束。`CORE-002` 已允许「另有已批准的管理规范」，无需修改。
- 内容发现规格新增 `DISC-053`：推荐响应可以携带 `SPEC-sponsored-ads` 定义的独立广告槽位；广告不是
  发现结果条目，不适用 `DISC-001`～`DISC-003`、`DISC-034`、`DISC-035` 的条目语义。
- [反馈可靠性规格](../spec/SPEC-feedback-reliability.md)新增 `REL-009`：广告曝光沿用 `REL-004` 的
  可见性定义，按（请求，目标类型，目标）去重；广告事件只进入广告统计，不进入推荐特征与训练集
  （呼应 `REL-011`）。`REL-020` 补充审核快照、审计记录与资质证件的保留期限。

# 理由

- 先审后投是广告合规的底线。结论绑定 revision 与快照，投放只读过审快照，才能保证投出去的就是审过的内容。
- 论文的级联让昂贵模型只处理少量高风险内容，但它面向先发后审：Router 放过就是不处置。广告是先审后投，
  Router 漏召会直接变成漏放，所以 `RVW-010`、`RVW-012`、`RVW-014` 把召回与放行分开，并用抽样质检
  估计漏放。论文的评估集只取自 Router 输出，作者也把漏召列为局限。
- 广告走独立的可选字段，旧客户端和帖子排序语义都不受影响，也避开了现有前端遇到非帖子条目整页失败的问题。
- 现有的 outbox、幂等、revision CAS、MySQL 租约、embedding/Milvus 与在线推理降级模式都可以复用。

- 根仓：本地栈新增进程、e2e 用例与跨仓证据。
- 知识链：批准后新增 `DES-review-platform`、`DES-sponsored-ads` 及对应 IMP；验证前条款保持 `unknown`。

# 实现预想（非条款，批准后在 DES 展开）

- 进程：`app/ad/rpc`、`app/ad/mq`、`app/review/rpc`、`app/review/worker`，以及
  `algorithm/moderation_infer`。
- Router 接缝复用现有 embedding 服务（384 维多语言文本向量）与新的 Milvus 种子集合，沿用 `_current`
  别名切换版本。Ranker 接缝按论文 Algorithm 1 返回每个 issue 的 Yes/No 概率；Python 占位实现沿用
  online_infer 的超时降级与故障注入测试。图片向量与质心选种先做占位。
- 人审租约沿用 `agent_run` 的 `FOR UPDATE SKIP LOCKED` 与 `lease_generation` fencing，另补尝试次数。
- 结论经 outbox 事件投递，广告域按 revision CAS 应用，不暴露置为通过的 RPC。
- 投放：Gateway 并行调用广告服务（短超时，失败时返回空）；槽位按页内相对位置分配；频控用 Lua 保证原子计数。
- 已知风险：本地 Milvus 为 v2.2.8，Go SDK 为 v2.4.2，测试容器为 v2.5.6，需要先验证 Upsert；
  `just infer-up` 不等待 embedding 端口就绪。

# 待人类决定

- 初始市场与政策矩阵，以及 issue 分类与政策码。演示政策不代表任何真实法域的法律要求。
- 默认值：
  - 质检抽样比例：建议不低于 5%。
  - 首次送审保护期：建议前 3 条。
  - 每日频控：建议 3 次。
  - 隐藏广告屏蔽期：建议 30 天，与 `DISC-035` 一致。
  - 下线传播上限：建议 60 秒。
  - 人审持有期限：建议 10 分钟。
- 回扫判定违规后，是先暂停投放再人审，还是人审确认后再下线。
- 审核快照、审计记录与资质证件的保留期限。
- 角色授予方式：建议初始政策管理员由种子脚本写入，之后由政策管理员在工作台授予；也可以全部经运维脚本。
- 落地页只做域名与 URL 结构校验，还是增加页面抓取。后者涉及 SSRF 防护与外部请求。
